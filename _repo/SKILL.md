# JSON Prompt Visualizer

把一段 JSON 布局提示词，变成**看得见、改得动、导得出**的画布。

> 当前有两个适配器：**MOSS-Image**（`summary` + `items`，layout prompt）和 **Klein**（`i2i_bbox`，图像编辑标注）。
> 骨架是通用的：任何"一段全局描述 + 一块一个 bbox"的格式，加一个适配器就能用。

## 先判任务类型（闸门，别跳过）

**MOSS 是文生图，Klein 是图像编辑。两条路互斥，判错就白干。**

| 判定 | 依据 | 该做什么 |
|---|---|---|
| **文生图（T2I）** | 没有母图，从零生成一张 | 只出 MOSS 提示词。**不要输出 Klein 编辑稿** |
| **图像编辑（i2i）** | 有一张（或多张）已有图，要改字 / 换物 / 挪位 / 删东西 | 才出 Klein 编辑稿，且**必须同时给出参考图端口映射表** |
| **认不出来** | 用户没说清，或描述里两种特征都有 | **停下来问一句**："这是文生图（从零生成）还是图像编辑（改已有的一张图）？" 拿到答案再往下做。**不要凭猜输出 Klein** |

导出面板「Klein 编辑稿」页签顶部是同一个闸门，默认停在「文生图」，此时该页签不出内容。

**出 Klein 时必须附端口映射**——提示词里写 `<Picture N>`（从 1 数），表格里的 `from` 是 `ref_image_N`（从 0 数），**两边差 1**，这是最容易接错的地方。
导出面板会自动生成这张表（`<Picture N>` ↔ `from` 值 ↔ ComfyUI 端口 ↔ 这个端口该接哪张图），
最后一列要由用户填实际图片路径，**空着不许提交**。

## 三步

| 你想干什么 | 命令 |
|---|---|
| **看见**：JSON 画成画布，框在哪、哪块是什么 | `python scripts/canvas.py draft.json` |
| **改**：拖动、缩放、加框、删框、调层级、撤销重做 | 打开生成的 HTML，点选即改 |
| **导出**：MOSS 提示词 / 草稿 JSON / Klein 编辑稿 | 工具栏「导出提示词」 |

```bash
# 最简：草稿 → 画布
python scripts/canvas.py examples/coffee_overlap.draft.json \
  --notes examples/coffee_overlap.notes.json -o canvas.html

# 编译稿（不带宽高）要补画布尺寸
python scripts/canvas.py prompt.json --width 1152 --height 1536

# 有出图时叠上去看，框和实物对不对比一眼就知道
python scripts/canvas.py draft.json --image 母图.png # 编辑任务里它就是 <Picture 1>
# 底图默认**内嵌进 HTML**（装 Pillow 则压到长边 1800 的 JPEG），拷到哪都看得到；--link 才用相对路径
```

`--notes` 是可选中英对照：`{"summary_zh": "...", "items": [{"caption_zh": "..."}]}`。
**中文只活在编辑器里，导出时会被剥掉**——官方编译器不认这些字段。

## 画布怎么用

- **拖**框体移动，**拖**四角缩放，数字框可精确到像素
- **双击**框 → 跳到对应字段（文字块落 `text`，物体落 `caption`）
- **Del** 删框，**方向键**微移（Shift 十倍），**Ctrl+Z / Ctrl+Shift+Z** 撤销重做
- **＋ 加框** 在画面中央加一个文字块；右侧图层列表点一下即选中
- **↑ ↓** 改数组顺序（**只是编辑器里方便摆放，不能控制前后**，见下节）
- **重叠闸门**：框一旦重叠，右侧「重叠与前后」会列出重叠区间；点「复制询问单」交给 skill 去定前后并写遮挡句

字段面板里每个输入都有中英对照：`caption`（英文，参与导出）与「中文参考」（不参与导出，但可以切到"导出用中文"）。
**中文参考不空着**：没翻译时会自动把英文原文带进输入框，直接在上面改成中文即可，不用对着空框猜。
导出用哪种语言，由顶栏的「导出用英文 / 导出用中文」决定，缺一边时自动回落。

`palette 主配色` 下面是一排**可点的色块**：点色块直接取色，`＋` 加一个，`×` 删一个；
上面的文本框与色块双向同步，手输十六进制也行。

## 前后关系怎么表达（重要）

**结论（已判定）：这套方式靠谱，保留。**
理由：MOSS 官方 layout 规范**没有 z 字段**，只写了"多个 item 可以共享或重叠一个框"。
既然没有 z 通道，**把遮挡写进 caption 就是官方唯一允许的表达式**——它不是实验技巧，是规范逼出来的唯一写法。

但两件事要分开看：

| 做法 | 判定 | 说明 |
|---|---|---|
| 往 caption 里写遮挡句（谁在前、挡住谁的哪一部分） | ✅ **靠谱，这就是机制** | 「挡住它 / 被它挡住」按钮干的就是这个 |
| 画布里上下挪动改数组顺序 | ⚠️ **不可靠** | 只方便摆放；官方没声明顺序能控制前后，别当保证用 |

按钮**照用**，但别以为拖一下顺序就有用。同一个按钮点多次不会重复叠加：
每次都会先把两种方向的旧句剥掉，只留最新一句；「挡住它／被它挡住」来回切也不会留下自相矛盾的两句。

想验证"顺序本身有没有用"，得单独出对照图，不能凭感觉下结论。

## 导出四个页签

| 页签 | 产物 | 给谁 |
|---|---|---|
| MOSS 提示词 | 单行 JSON（`abs_centralized` + `yxyx`，中心原点） | 直接贴 ComfyUI 的 `CLIPTextEncode` 正向框 |
| 草稿 JSON | `abs` + `xyxy` + `width/height` | 存下来／交给脚本继续改（`canvas.py` 能直接打开） |
| Klein 编辑稿 | 指令段 + 一格表（`0–1000`、`[y,x,y,x]`）+ **参考图端口映射表** | **仅在图像编辑任务**时交给 Klein 做框内改字/换物；文生图任务不出这一项 |
| 中文参考 | `notes.json` | 下次 `--notes` 传回来，中文不丢 |

导出前会跑一遍校验：画布尺寸是不是 16 的倍数、框有没有越界、文字块有没有 `text`、caption 是否为空，
外加"框太矮字会很小""单块字数过多""没有全画布背景"这类提醒。**有错就不给编译**，不静默放过。

## 边界

- 不出图、不联网。它只处理 JSON、坐标和预览。
- 中文参考不参与导出，别把唯一文案只写在中文字段里。
- 画布宽高必须是 16 的倍数；越界框会被拦下，这是有意的。
- 换画布尺寸**不会**等比缩放 bbox（坐标是绝对像素），要缩放请先改框再改尺寸。
